# Quick Task 261019-o31: Architekturschaubild TradingEngineX mit umgesetzten Anforderungen als Artefakt - Context

**Gathered:** 2026-10-19
**Status:** Ready for research and planning

<domain>
## Task Boundary

Ein vollständiges Architekturschaubild von TradingEngineX als interaktive Artefakt-Seite (HTML). Es zeigt,
welche der ursprünglichen Anforderungen umgesetzt sind, und beantwortet die Operator-Frage, wie weit
stochastische und heuristische Vorhersagemethoden sowie eine semantische Auswertung von Ticker-Meldungen
(News, Social, Fundamentals) tatsächlich verwendet werden.

</domain>

<decisions>
## Implementation Decisions

### Anforderungsumfang
- **Alles inklusive Upstream:**
  - M1 „Produktionsreife“ (`.planning/MILESTONE.md`, P1/P2-Punkte).
  - M2 „IBKR Paper Execution“ (`.planning/REQUIREMENTS.md`, REQ-IBKR-xx).
  - Die Funktionen aus Upstream TradingAgents: Analysten, Debatten, Trader, Risiko, Portfolio-Manager, Memory/Settlement, Backtest, CLI, LLM-Provider.
- Jede Anforderung bzw. Funktion bekommt einen Status (umgesetzt / teilweise / offen / bewusst verworfen bzw. Override) mit Herkunft (Upstream / Strang), Phase oder Quick-Task und Nachweis (Datei, Commit oder Test).
- Der Status wird am Code und an den `.planning`-Artefakten belegt (VERIFICATION/SUMMARY/ROADMAP), nicht geraten. Phase 6 läuft gerade parallel: Stand zum Erstellungszeitpunkt mit Datum und HEAD-SHA ausweisen.

### Darstellung
- **Interaktive Seite:**
  - Ein großes Architekturdiagramm: Upstream-Kern, Strang-Module (Jev, Patterns, Budget, State-Maintenance, IBKR-Ausführer …), GitHub Actions (täglicher Paper-Lauf → `paper-log`), lokaler IBKR-Ausführer mit IB Gateway, Datenquellen, Datenflüsse.
  - Darunter eine filterbare Anforderungsmatrix. Ein Klick auf eine Komponente zeigt ihre Anforderungen.
  - Dazu ein eigener Abschnitt „Vorhersagemethoden“.
- Die Daten liegen eingebettet in der Seite (statisch, keine Runtime-Capabilities nötig). Die Seite muss in beiden Themes und auf Handybreite funktionieren.
- Die Seite selbst ist deutsch.

### Methodenteil
- **Ehrliche Bestandsaufnahme.** Je Methode:
  - wo sie im Code steckt (Datei),
  - was sie tatsächlich tut,
  - ob sie die Entscheidung beeinflusst oder nur Eingabe bzw. Nachauswertung ist,
  - was fehlt.
- Abzudeckende Methoden:
  - **Stochastisch/statistisch:** gibt es Wahrscheinlichkeitsmodelle, Monte Carlo, Volatilitätsmodelle? Dazu Wilson-Intervall und Settlement-Statistik.
  - **Heuristisch:** technische Indikatoren als LLM-Eingabe, `tradingagents/patterns/` (Nachauswertung, keine Entscheidung), `post_screen`, Jev-Checks, Leitplanken.
  - **Semantische Auswertung von Ticker-Meldungen:** News, Social und Insider über LLM-Analysten. Gibt es eigenes NLP, Sentiment-Scores oder Embeddings?
- Keine Empfehlungsliste, nur die Lücken benennen.

### Claude's Discretion
- Visuelle Gestaltung, Diagrammtechnik (Inline-SVG oder Mermaid) und Gruppierung der Komponenten.

</decisions>
