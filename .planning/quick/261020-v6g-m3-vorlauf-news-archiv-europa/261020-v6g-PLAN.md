1. Zu Beginn des Tasks:

2. Stagen nur mit `git add -- <erlaubte Pfade>`.
3. Danach `git diff --cached --name-only` ausführen. Jeder Pfad muss in der Erlaubt-Liste stehen. Steht dort ein fremder Pfad, den die parallele Session gestaged hat, NICHT unstagen (fremde Arbeit), sondern weiter mit Schritt 4: Der Pathspec-Commit nimmt ihn nicht mit.

5. Done-Prüfung:
   - `git diff --name-only START_<n>..HEAD` listet ausschließlich Pfade aus der Erlaubt-Liste.
   - `git status --porcelain` für fremde Pfade ist identisch mit dem „Fremdstand vorher“. Ein sauberer Arbeitsbaum wird nicht verlangt, weil die parallele Session dort arbeitet.

Unterbefehl `run [--catch-up] [--sources gdelt,amf] [--max-days 3] [--max-runtime 150] [--seed PATH] [--limit-issuers N] [--start YYYY-MM-DD]`:
- Catch-up ist immer aktiv; `--catch-up` wird nur zur Lesbarkeit des Scheduler-Aufrufs akzeptiert.
- `--max-runtime` in Minuten (Default 150, unter dem ExecutionTimeLimit von 3 h). Daraus wird eine `deadline` auf `clock` berechnet und an collect_day/collect weitergegeben. Bei Ablauf endet der Lauf sauber: Status des laufenden Tags `partial` mit `max_runtime` (ohne Versuchszählung), Heartbeat geschrieben, Lock freigegeben.
- Ablauf:
  1. RunLock auf `archive_base()/run.lock`; bei LockHeld → Exit 3. `lock.touch` geht als `on_progress` an die Collector.
  2. `ensure_archive_start` mit `--start` oder, falls nicht angegeben, gestern UTC.
  3. Heartbeat „started“ schreiben; `last_finished_at` bleibt erhalten.
  4. Je Quelle `days_needing_work(..., window_days=89 für gdelt, max_days)` bestimmen. GDELT ruft `collect_day` je Tag auf, AMF `collect(days, today=...)`.
  5. Jede Quelle läuft in eigenem try/except: Eine abgestürzte Quelle schreibt für ihre Tage Status `missing` mit Fehlertext, die andere läuft weiter.
  6. Heartbeat „finished“ mit run_id, started_at, finished_at, last_finished_at=finished_at, exit_code und Zählern je Quelle.
- Exit-Codes:

  | Code | Bedeutung |
  |---|---|
  | 0 | alle bearbeiteten Tage ok |
  | 1 | mindestens ein Tag `partial` |
  | 2 | mindestens ein Tag `missing` |

- run_id: `run-<UTC-Zeit>-<pid>`.
- `now` ist injizierbar; „heute“ ist `now().date()` in UTC.

Unterbefehl `backfill --source gdelt [--max-calls N] [--max-runtime 150] [--seed PATH]`:
- Ohne archive_start → Exit 4 mit dem Hinweis, zuerst `run` (gegebenenfalls mit `--start`) auszuführen.
- Ruft `gdelt.backfill` unter dem RunLock auf und gibt eine Fortschrittszeile aus (`done/total/expired`).

Unterbefehl `backfill --source amf --since YYYY-MM-DD`:
- Ruft `amf.collect` für alle Tage seit since mit `backfilled=True` auf.

Unterbefehl `status [--days 14]`:
- Gibt eine Tabelle Tag × Quelle aus `gap_report` aus: ok/partial/missing, attempts, Zähler inklusive truncated.
- Dazu archive_start, der letzte Heartbeat und das Heartbeat-Alter (ab last_finished_at) sowie der Backfill-Fortschritt aus dem Checkpoint.
- Exit-Codes, in dieser Reihenfolge geprüft:

  | Code | Bedingung |
  |---|---|
  | 2 | kein fertiger Lauf oder letzter `finished_at` älter als 36 h |
  | 1 | mindestens ein Tag partial/missing |
  | 0 | sonst |

Unterbefehl `smoke [--issuers 2] [--seed PATH]` (per D-10, Checker-Blocker 1):
