`resolve_entry(entry, history) -> Resolution` in `scripts/ibkr_ledger.py`: `key = entry["order_ref"]` (fällt auf `entry["decision_key"]` zurück, falls `order_ref` fehlt). Treffer je Quelle über exakte `order_ref`-Gleichheit (clientseitig, weil der Ausführungsfilter des Brokers kein `orderRef` kennt, Research Pattern 6). Reihenfolge:
1. Kollision: ein Treffer in irgendeiner Quelle mit `con_id` ≠ Eintrag, oder Aktion/Seite ≠ `entry["side"]`, oder (bei Orders) `quantity` ≠ `entry["quantity"]` → `COLLISION` („orderRef is not unique at IBKR“, REQ-41).
2. offene Treffer und gleichzeitig erledigte Treffer → `CONTRADICTION`.
3. offene Treffer → `OPEN`.
4. Summe der Execution-`shares`: > Menge → `CONTRADICTION`; == Menge → `FILLED_OUT`; 0 < Summe < Menge → `PARTIAL_OUT`.
